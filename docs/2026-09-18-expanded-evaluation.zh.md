## 测试中修复的三个运行时问题

1. **同名标题取不到正确段落。** 原 `chunk_id` 只用来源/文件/标题计算，同文件重复标题会撞。现在搜索另带内容指纹 `chunk_md5`，读取可精确定位，内容变过则要求重新搜索。原标题/唯一前缀读取保持兼容。
2. **凭据格式脱敏有漏口。** 早期私有测试中，内联账号密码进入过模型上下文并被回显。索引、读取和模型边界已补齐对应格式，所有来源统一处理；本轮已知明文副本已清理，原始用户笔记未改。历史模型传输无法撤回，仍有效的已暴露凭据需要轮换。格式检测仍不能识别所有未标记秘密。
3. **PDF 查询给无关资料算大模型向量。** 旧实现首次 PDF 查询在 300 秒内未返回；现在 PDF 向量实例只处理 PDF，并把局部索引映射回全语料位置。普通检索、股票统计、融合和 rerank 预算不因此更改。复测的首次 PDF 调用仍约 98.8 秒（含剩余缓存生成），其余该组 PDF 查询约 3.9–5.0 秒。缓存与系统负载不同，不用这两组数字宣称严格提速倍数或性能预算已达标。

## 最值得继续做的事

1. **先修股票元数据匹配。** 当前 ASCII 分词会把示例文件名拆成 `card_demo`、`short_2026-01-01.md`，而用户问的是 `demo`、`2026-01-01`。稀疏卡片正文又可能没有代码和日期，造成“资料在磁盘上却找不到”。应单独解析股票代码、卡片日期和周期，按请求约束过滤/加权；同时清理卡片内跨标的/跨周期转载的歧义。不要由此泛化成给所有笔记加完整标题路径。
2. **答题时限制无必要的额外断言。** 对每条断言核对实体、时点和证据范围，尤其不能从当前价推出整个窗口未触发，不能混用不同周期数字。先做句子与引文的支撑检查，再讨论生成模型微调。
3. **让独立作者补真实失败题并复核标签。** 补有效替代段落、同义事实和跨来源重复组；已测题归回归集，下批独立题冻结后只验收一次。36 题和 24 组不是质量保证阈值。
4. **继续测真实宿主 agent 与尾延迟。** 本轮是固定“搜索→读取→答题”流程，不代表每个客户端会自主执行同样步骤。PDF 首次加载和暖查询仍慢，之前 2 秒/4 秒预算也没有因此重新宣称通过。
