# 股票卡片匹配与逐句引用检查

本次需求有两项：修复股票代码、日期、周期在文件名里粘连造成的漏检；逐句检查引用是否支持结论，尤其避免跨日期拼数字、拿价格快照推断整个交易窗口。原题、股票 draft 状态和已消耗的盲测标记保持原样。

这是 RAG 调优，没有训练模型或改变模型权重。卡片字段解析及交易窗口规则适配本地股票业务；按句绑定引用、区分出处正确与结论正确的办法可以用于其他业务。具体解析规则和已测效果不等于对任意问答的通用提升。

## 找到正确卡片和答案段落

`card_TEST#short_2026-09-17.md` 分别提供 `ticker=TEST`、`card_date=2026-09-17`、`horizon=short`。旧的 `#MID#mid` 标记、带市场后缀的代码也能解析。字段只补到股票 BM25 词项，不改 embedding 输入、模型或缓存版本；普通笔记的 BM25 统计仍独立。

股票导出器的“入／损／站上”分别增加“入场／止损／站上线”词项，且只加在实际包含数值字段的段落。否则即使卡片找对，“在途”这种短段落也可能因长度优势压过真正的数字。

`memory_search(source="stock")` 对明确问卡片、计划、复核或计划价位的单一代码与单一日期/周期查询，给词法、向量两条腿使用同一范围。带日期的新闻/公告问题不自动限定为卡片；多日期、多周期及时间范围问题保持宽搜，避免把比较问题错误缩成一张卡。返回值的 `stock_filter` 显示实际应用的范围；命中的 `stock` 显示卡片身份。

调用者也可以明确传入：

```json
{"query":"历史参考入场区和止损", "source":"stock",
 "stock_filter":{"ticker":"TEST","card_date":"2026-09-17","horizon":"short"}}
```

不存在该卡时返回空结果，不能拿相邻日期/另一周期冒充。`card_date` 是卡片日期，不是正文每个价格、成交或事件的发生日期。自然语言范围解析采取有限规则；复杂比较应由调用者明确拆分查询。

## 逐句检查的实际入口

MCP 新增 `memory_check_answer(question, answer, evidence)`。流程为搜索、读原文、起草分条结论、检查、修正或说明证据不足。每条结论带它自己的逐字引文；不要用另一条结论的引用补证。

`answer` 与答题评测使用同一 JSON 结构：`decision`、`claims`、`reason`。`evidence` 只接收资料位置，不接收调用者自编的正文：

```json
{"question":"这张历史卡记录的止损是什么？",
 "answer":{"decision":"answer","reason":"","claims":[
   {"text":"卡中参考止损为 90。",
    "citations":[{"evidence_id":"e1","quote":"参考止损 90"}]}]},
 "evidence":[{"id":"e1","source":"stock",
   "file":"card_TEST#short_2026-09-17.md","heading":"判断",
   "chunk_md5":"用搜索返回的32位指纹替换"}]}
```

服务端重读实际来源，Markdown 可用指纹拒绝过期段落；PDF 一页一个编号，只核对指定页，邻页不能冒充该页。逐句输出引文问题、缺少来源的数字、日期对应问题、跨卡引用和未获证据支持的交易窗口结论，不新增大模型调用。

例如，引文只有“当时价 105，站上 110，回踩 95–98”，不能据此说“整个窗口都没触发”；前一天卡片里的“待确认”，不能自行变成后一天“已二次确认”。“收盘低于 95 就退出”是计划条件，不应被误判为某日收盘价。

`checks_pass=false` 要求修正或补证；`true` 只表示未发现这些确定性反例。自然语言否定、隐含条件、计算、相对日期和跨句因果仍可能需要语义复核。规则不自动证明任意改写，也不保证原始资料符合外部事实。旧客户端需要刷新 MCP 工具列表，调用者仍须实际执行检查流程。

## 评测如何防止整题的绿灯掩盖坏句

`grade_answer` 共用检查器。严格文本评分不再让无关结论捐出引用，使另一条错误引用的结论过关。需要多个句子说明的事实仍可合并，但贡献句各自必须引用支持它的同一来源段落。

新结果的语义复核必须提交 `sentence_reviews`，逐项记录 `claim`、`sentence`、`supported`、`scope_correct` 和来源理由；任何句子漏审、重复或判错后却把整题写成支持正确，报告都会拒收。旧的封存结果仍可读取，不悄悄用新口径替换旧分数。

公开测试使用虚构价格与资料。实际题目、源文和回答保留在私有验收目录。验证优先跑相关股票回归、实际 MCP 的三个漏检案例和四次针对性生成，避免重新扫整套模型 A/B；这些题都已见过，只能叫回归测试。

运行无模型单测：

```powershell
py -3.12 scripts/verify_unit.py --output <private-results.json>
```
