## 先补尺子，再动检索参数

普通 23 题已逐条按原文补齐段落标签，保存于忽略的 `golden/private/notes-evidence.json`，不改原 59 题。新标签由同一 agent 在检索实验前核验并封存，不是独立人工裁决。旧 `golden_evidence.json` 仍保留原八项检查，其中只有四道段落正例；主集本身仍是文件级标签。需要多段共同回答的问题用 `evidence_groups`，只找到其中一段不算完整证据。标签覆盖 23/23 不等于证据命中 23/23，更不等于最终答案正确率。

下一批候选必须用 `mr.py mine-transcripts --unranked`：原命令会先检索、按难度选题，不能把其输出直接当盲测。独立留出未参与调参的事件组，标为 `split="blind"`，冻结 query、标签、`case_group` 与 SHA；同一事件的改写、复制和切片不能跨组。`scripts/sealed_eval.py` 在首次检索前以排他方式写入消耗标记，中断或失败的尝试也不能再次冒充盲测。当前留出三道真实问题，由同一 agent 标注，只是小规模结果留出，不是第三方盲测。现有 59 题不能改名冒充 blind。

## 股票 BM25 对普通笔记的耦合

当前 `source=stock` 继续使用全部非 PDF 文档的 BM25 统计，是为保留股票草稿基线的暂时兼容策略，不是理想边界。以下任一条件触发重新做定向统计对照：

- 新增/删除普通笔记来源，或改变切块规则。
- 股票语料和标签没有变化，但笔记变化伴随股票前五命中或 MRR 下降。
- 股票草稿经原文核验完成，补齐 ticker、日期/周期、必需证据和可接受替代案例。
- 同一冻结股票集上 hybrid 的排序弱于 BM25 单腿，即使 hit@5 一样，也触发融合与来源统计的消融；不要等普通笔记变化后才检查。

对照必须冻结相同股票与笔记内容，比较现有混合统计、股票独立统计及必要的固定参考统计。保留原标签；只有文件/日期/证据与阴性检查都通过，才切换。此前独立股票统计造成退步，不能因“按源独立更整齐”就默认采用。

## 实验顺序

| 顺序 | 实验 | 固定项与验收 |
|---|---|---|
| 1 | 段落级重叠（HA p290） | 先扩充段落标签。只替换超长标题块的字符硬切策略；优先保留完整段落，超长单段再按句界兜底，仍有明确大小上限。检查 required_text 的预览覆盖、原文可重建性、文件/页码命中、缓存失效版本与索引成本。对照旧 1500/150 切法，不能只看文件级分数。 |
| 2 | rerank 延迟预算 | 先定切块，再在固定语料/CPU/模型版本上扫三个旋钮：max_length 512→256、候选数 5→3、每块窗口数 3→2。跑八组组合；旧阈值只用于候选对照，不算部署验收。选定最终参数后统一标定并冻结 hi/lo，复跑 23 普通正例、段落标签与 12 阴性，最后消耗留出集一次。 |
| 3 | MQE / HyDE（HA p293–296） | 保留关闭的默认路径。扩展内容按原问句、生成模型版本、prompt hash、参数与语料/索引版本持久缓存；评测只回放缓存，缺缓存直接失败，不临时生成。比较真实返回/段落命中、错误近邻、调用数、tokens 和延迟。任务估时 ≤2h 是候选实验预算，不是已有结果。 |
| 4 | recency × importance | 最后做。先有明确时间标签和时间敏感问题；现有金标不偏时间，不能用它证明时间项收益。要区分“新近”与“有效”，不能让近期片段自动覆盖仍有效的规则。 |

扩展查询缓存需要可复跑的版本记录；涉及私有股票或个人问题的缓存留在私有存储，不能因教材写“提交缓存”就混入公开仓。

## 延迟预算及测法

实验目标：暖查询 p50 ≤ 2 秒、经验 p95 ≤ 4 秒，新进程首查 ≤ 60 秒。它们是预算，不是达标声明。旧 MCP 六次样本仅为三题各两次，其 nearest-rank p95 就是最大值，不能证明稳定尾延迟。验证器现改为八道正例、四道阴性各三次，共 36 次串行暖查询；记录总耗时、rerank 耗时、pairs、额外段落数与逐次语料 SHA。12 道题的重复样本仍不能代表所有真实流量。

当前脚本的首查是股票 BM25、`rerank=false`，包含服务预热；暖机样本才使用 hybrid+base gate。默认 hybrid 加首次 rerank 的完整冷启动须在后续受控实验中另测，不能把这两种首查混称为同一基准。

用户 2026-09-18 复核测到冷启约 60 秒，暖查询 3.86/2.78 秒，rerank 3.46/2.73 秒，12 pairs 约 270ms/pair。这些有明确来源的观测构成优化动机；质量对照脚本复用响应缓存的均值不能替代它们，也不能用“不是性能基准”略去预算。

验收同时要求：证据命中不退步，已答对正例不新增 low，阴性误 high 不增加。速度达标而质量失败不得启用；质量通过而速度未达预算，要明确留作性能待办。

三个旋钮的代价不同：候选数减少可能不看第 4/5 名；输入长度减少可能截掉窗口后半段；窗口数减少不改候选集，但块中后段可能失去评分。时间不能按简单乘法承诺，CPU 批处理、padding 和机器负载都会影响结果。保存逐题原始分数，才能重标定和追查漏掉了哪段。

本轮八组静态对照发现：256/3/2 会新增一道 low 正例，不能直接部署。追加的通用保护为“先评前三条，若最高分低于 lo，再补到原前五条”，而非为这道题降低门槛。补查仅限实际返回的候选；topk=2 时第 4/5 条不能抬高置信。最终配置另做统一标定与全量回归，静态候选的快成绩不能冒充带补查后的实际速度。

跨来源检查又拦住了一次退步：短输入用于 PDF 时新增一道 low 正例。因此最终提速只作用于普通笔记；PDF/stock 保留原长度、候选数和窗口数。各来源共享权重但分开预算，输入长度逐次设置并受锁保护；不能让 PDF 调用遗留的 512 token 配置悄悄影响下一次笔记查询。

向量的作用也按来源看：普通集曾在 MRR 几乎相等时补回两个文件命中，说明有覆盖收益。这个单次对照不能推导 embedding 微调的理论上限；股票集的负贡献则支持先测融合配置，而非立即训练或全局关向量。

## 置信、污染与公开交付边界

- base gate 的 0/12 阴性 high 是检索侧标注结果；不启用它时仍可能有 high。调用 agent 是否在 low 时拒答、是否忠实引用，是另一层尚未完成的答案评测。
- 热更新会检查已知问句并告警，默认检索不因告警自动改排序或屏蔽材料。逐字匹配会漏改写，也可能命中正常答疑中的原问题；必须核对用途，不能为通过检查就把真实知识改成 evaluation。
- 质量对照和 MCP 调用各有自己的语料身份记录，前一轮稳定不能证明后一轮也稳定。
- 公开远端曾与 `dbf2b6b` 一致。旧金标含内部来源文件名与事件描述，这是既存公开历史；本轮新增全文证据、留出题和原始结果只留私有目录。未重写 Git 历史或改变仓库可见性，公开历史清理仍是独立交付事项。
