# 2026-09-18：段落切块、有限补查与验收边界

本轮在 `dbf2b6b` 的四项修复上继续优化。以下是本机私有资料的实测，仓库不含原文、完整新增标签或逐条检索结果。机器为 i7-13700HX，PyTorch 2.13 CPU、16 个推理线程；未换模型或使用 GPU。

## 已实施

- 普通笔记的长标题块优先按段落边界切分，并保留有上限的整段重叠；超长段落按句子/行处理，极长单句才硬切。股票/PDF 保持旧边界，未采用已被实验证伪的完整 heading_path。
- 普通笔记 base gate 改为 256 token、每块两窗，先看三候选，最高分低于 lo 时补到原前五候选；评分范围不超过实际 topk。PDF/股票保持 512 token、五候选、三窗。同一模型的预算变体共享权重，按次恢复 token 上限。
- 补齐普通 23 题的私有段落标签，支持多段共同作答；原 59 题与旧八项专项检查保持不变。MRR@10 在第十名截断。
- 首次加载/热更新检查已知问句污染，告警与检索解耦；search 返回语料 SHA 和审计状态。用途标签仍需核验，逐字引用不一定是污染，改写仍可能漏检。
- 增加不检索的 transcript 挖题入口、一次性封存评测入口，以及远端 SHA/可见性、逐次 MCP 语料身份和提交状态检查。

## 拒绝的省事方案

- 256/3/2 静态预算把一道已知正例降为 low，因此加入按需补查，没有按这题的分数硬压低 lo。
- 把短预算套到 PDF，会把一条正例由 high 变 low；已撤回跨来源应用。旧 PDF gate 本来就有一条 low 正例，页命中全中不能掩盖它。
- BM25 强行按文件去重虽能达到 22/23 文件命中，却将段落命中从 9/23 降为 6/23；限制每文件两块也丢证据，均未采用。纯 BM25 的退步及向量不可用时的回退风险仍在。
- 股票独立 IDF 再测仍将 hybrid 从 11/12 降为 10/12；保留旧统计。股票 BM25 MRR 0.875 高于 hybrid 的差距加入重测触发条件。
