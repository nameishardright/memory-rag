# 段落与最终回答评测

检索验收分三层：正确资料是否在前五条；返回预览是否包含必需事实；读取完整段落后，模型是否答对、引用是否支持结论、证据不够时是否拒答。三层分别记分，不能用文件命中率或 `confidence` 代替最终回答正确率。

## 题目与来源

原 59 题保持原样。普通笔记、PDF、股票的段落标签放在忽略的 `golden/private/`；股票原集继续保留 `draft=true`。新增题必须记录 `id`、`case_group`、`split`、来源范围 `source_units`、支持答案的段落及 `answer_contract`。构造题、日志挖出的原问句、人工独立出题要如实区分；同一个事件换三种问法算三道题、一个事件组。

正例的 `answer_contract.facts` 同时标出回答应包含的事实表述和支持它的原文。允许同义说法与多个正确来源，但标签必须在看检索结果前核对。阴性题写明缺失的证据和容易混淆的材料：历史记录不能证明当前状态，演示代码不能证明用户实际运行结果，研究计划不能证明成交。

来源范围不只看答案文件。股票同一标的的不同日期、不同周期卡片应属于同一事件谱系；教材用已审阅的章节或页区间隔离；笔记按整个文件隔离。相同问题、事件组或来源范围跨开发/盲测集会报错。这些检查无法自动识别所有跨文件改写、教材与笔记的语义重复，仍需原文审阅。

## 两条固定流程

`scripts/eval_answers.py` 通过真正的 stdio MCP 调用 `memory_search`，保持同一搜索结果，再比较：

- `snippet`：模型只读前五条预览。
- `passage`：对同样的前五条调用 `memory_get`，模型读完整段落；Markdown 原样传递搜索返回的 `chunk_md5`，PDF 按实际页码引用，邻页有各自的证据编号。

两条流程使用相同提示词、模型入口和输入上限。每个请求开独立会话，不传金标、不传置信标签、不开放文件或网络工具。生成端只能看到问题、真实返回的材料及来源位置。模型身份、输入哈希、原始输出和引用保存在私有结果里。它评估的是固定的“搜索→读段落→回答”流程，不代表任意宿主 agent 都会按此方式调用工具。

上下文总量上限为 18000 字符，单段/页最多 6000 字符，并记录截断。PDF 返回页邻居时，每页单独编号，防止邻页的原文冒充中心页证据。获取失败单独记录，不偷偷用预先标注的正确资料补上。

## 评分边界

确定性评分检查必需事实、实际引用的来源位置、逐字引文、预先规定的错误模式及拒答行为。同一事实可以分散在多条回答和同一证据段落的多条有效引文中，不能要求模型按标注者的一句话句式作答。未知证据编号、伪造引文、拿相似文件冒充正确来源、漏掉一项必要事实，都不能通过。`insufficient` 必须解释证据缺口并且不能夹带猜测答案。

`contract_pass` 是可复现的严格文本与引用检查，不能直接改名为语义正确率。自然语言里的否定、改写和额外断言仍需逐条复核，人工/agent 语义复核另存结果。不能因为看到输出用了另一种正确说法，就悄悄修改冻结标签然后重报盲测分数；保留原分数，另报裁定与理由。

## 扩大测试发现的运行时问题

同文件可能重复使用完全相同的标题，旧 `chunk_id` 只依赖来源、文件与标题，不能区分这样的段落。Markdown 搜索现在另返回 `chunk_md5`（内容定位指纹，不是访问凭证）；`memory_get` 和 CLI `get --chunk-md5` 用它定位具体内容。内容已经变化时返回 `stale_reference`，要求重新搜索；不悄悄读同标题的新版本。原有精确标题、唯一前缀与全文读取继续可用。

凭据脱敏不能只依赖“这个来源一般有没有秘密”。索引和读取现覆盖所有来源，并补上内联账号密码、带认证的 URL、JSON/带空格的引用值和认证头。截断后的片段再次检查占位符，模型调用前有独立检查，输出记录也做结构化脱敏。这覆盖了本轮复现的格式，不能证明任意未标记的随机字符串都是安全的。原始笔记保持原样；发生过的模型上下文传输无法撤回，仍有效的已暴露凭据需要另行轮换。

PDF 向量路由现在只编码 PDF 块，并把局部结果映射回全语料的索引位置。过去先对全语料编码、再过滤掉普通笔记和股票，首次切到大模型会做大量无用计算。PDF 局部向量索引与全量索引使用不同实例、共享同模型权重/增量缓存，热更新时保留来源范围；BM25 统计、融合和 rerank 预算不因此改变。纯向量、hybrid、热更新与位置映射均需回归，不能把静默回退算成功。

## 冻结和运行

所有原始资料、题目和结果均留在本地私有目录。命令文件是一个 JSON 对象，包含 `argv` 数组、`output_format`（`text` 或 `claude_json`）和超时秒数。`{system_prompt}` 会替换成固定答题提示词；问题与材料通过 stdin 传入，避免 shell 拼接。工具关闭、自动加载上下文关闭应由被测模型命令显式设置。

开发集可重跑，但每次保存独立产物。盲测需先 `--freeze --seal <manifest>`，冻结题目、开发参考集、代码、命令配置、提示词和原文清单；随后用同样参数运行一次。消耗标记在检索之前写入，进程失败也算已用过，后续只能归入回归测试。不能重建一个新 seal 把同一批已见结果伪装成盲测。

示例（各路径应指向自己的私有快照）：

```powershell
py -3.12 scripts/eval_answers.py `
  --dataset golden/private/expanded-development.json `
  --frozen <snapshot/markdown> --pdf-cache <snapshot/pdf-text> `
  --snapshot-manifest <snapshot-sha256.json> `
  --models <local-model-cache> --cache <isolated-eval-cache> `
  --output <private-results.json> --command <private-command.json>
```

不传 `--command` 时只测检索与完整段落证据，可用于原题回归。`harness_complete=true` 只表示所有请求都已记录且输入未变；模型生成或格式失败仍计入分母，`all_generations_valid` 另报，不能删题或重试盲测。质量验收必须另外看各项结果。此次答题耗时不作为之前检索 2 秒/4 秒预算的性能基准。

## 后续补题规则

先从真实失败、用户改问和缺证据时的行为补题，再考虑扩大数量。每一批保留未参与调参的独立事件；已验收过的题转回归，不重复计作新盲测。正式验收仍需要独立作者/用户确认标签，并在真实宿主 agent 上验证工具选择、时间范围和拒答。书中或历史记录本身不一定正确，引用忠实性与外部事实正确性也要分开。
